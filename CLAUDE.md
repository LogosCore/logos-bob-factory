# CLAUDE.md

BOB (`github.com/logoscore/logos-bob-factory`): a bare Logos factory (the module type that builds minions). `cmd/bob-factory/main.go` runs factory-core's `factory.Run` as module_name `bob`, with its own management and the live log tail (module-core `logging.New` teed into a `logstream.Hub`). `build.go` holds its build schema (targets `dummy` and `dummy-lite` on `any/any`, and `linux-elf` on `linux/amd64` / `linux/386`, all building the same dummy JSON; one field of each build field type; HTTP connection parameters `method` and `path_prefix`; commands of each kind: required, default, operator-picked, some targets only), its plan (`Steps`: check the badge when there is one, take punches while `build_delay` is set, describe the minion, compile it for `linux-elf`, upload), and the builder, which reports those steps and uploads a JSON description of the minion as the artifact. For `linux-elf` it instead compiles `cmd/bob-factory/stub` (embedded; `compile.go`) with the description baked in, for the build's platform, and uploads the binary; so BOB's image keeps the Go toolchain (`golang:1.25-alpine`), and the compile tests need `go` on `PATH`. `icon.go` holds its icons (constant SVGs sent at registration: `icon`, the lit skin, for dark themes, and `iconLight`, the outline, lines and shading, for light ones; a test checks both against `protocol.ValidateIcon`). `management.go` is BOB's own manifest: `build_delay`, `fail_builds` and `log_level` (live), and the `say_hello` action; factory-core adds the builds section (`max_concurrent_builds`, `drain`/`resume`, build counters) next to it, so BOB's manifest cannot use those keys.

Factory plumbing (build requests, progress, results, files, artifacts) stays in `logos-golang-factory-core`; module plumbing in `logos-golang-module-core`. BOB only declares what it builds and builds it.

Build and test: `go build ./... && go vet ./... && go test ./...`. Go 1.25.7. Config is env only (see README). Builder tests use `factorytest.Run` (or `Build`), which runs the real builder through the SDK in process and returns the plan, the progress and the result.
